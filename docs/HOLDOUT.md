# 홀드아웃 프로토콜 · 전진 추적 원장 (명세)

## 왜 필요한가

2026-09-25의 평가([EVALUATION.md](EVALUATION.md))에서 하이퍼파라미터를 정할 때, 평가와 **같은 기간과 같은 종목**을 보고 정했습니다.
정한 값은 다음과 같습니다.
- 폴드 배치
- 시장 드리프트 사전값과 축소 비율
- ν 하한, α, min_leaf

그래서 2014–2026 가격 데이터는 전부 "이미 본" 데이터입니다. 과거 구간을 나중에 떼어 "홀드아웃"이라고 부르면 결과를 과대평가하게 됩니다.
이 명세는 두 종류의 홀드아웃을 정의합니다. 각 홀드아웃에서 무엇을 봤는지는 **감사 가능한 기록**으로 남깁니다.

| 종류 | 무엇이 미사용인가 | 강도 | 결과 시점 |
|---|---|---|---|
| **전진(시간) 홀드아웃 FTH** | 등록 시각 이후의 모든 가격·뉴스 | 강함: 진짜 미래 데이터 | 만기(20거래일)부터 누적. 판정은 사전 등록한 최소 표본을 채운 뒤 |
| **횡단면 홀드아웃 XSH** | 튜닝 유니버스에 한 번도 없던 종목(시점별 유니버스 기준) | 중간: 같은 기간이라 시장 요인을 공유 | 즉시, **1회만** |

## 동결(freeze)과 지문

- **설정 다이제스트**: `Settings.digest()`를 그대로 씁니다.
- **신호 코드 지문**: `src/quantcio` 아래에서 **신호를 만드는** `.py` 파일의 해시입니다.
  - 제외: `report/`, `cli.py`, `evaluation.py`, `holdout.py`, `tracking.py`, `xsh.py`
  - 포함: 데이터 공급자. 입력이 바뀌면 신호도 바뀌기 때문입니다.
- **git 커밋**: 커밋 해시와 작업 트리의 dirty 여부를 기록합니다. dirty 상태에서 등록하려면 `--allow-dirty`가 필요하고, 기록에 그 사실이 남습니다.
- 평가나 추적을 할 때 현재 다이제스트·지문이 등록값과 다르면 **해당 홀드아웃에 대해 무효**입니다.
  - 평가 명령은 실행을 거부합니다.
  - `--force`로 실행할 수 있지만 그 결과는 `contaminated`로 기록됩니다.

## 사전 등록 판정 규칙 (primary_metrics)

아래 규칙은 등록 시 레지스트리에 함께 저장합니다.

**유효 표본 조건**
- 판정은 **겹치지 않는 스냅샷 날짜 기준 12개 이상**일 때만 합니다. FTH는 20거래일 간격이므로 약 12개월이 걸립니다.
- 그보다 적으면 결과를 "판정 불가(표본 부족)"로 표시합니다.

**주 지표** (나머지 지표는 참고용입니다)
1. **종목 선택**: 날짜별 μ_excess 순위 IC. 평균의 t ≥ 2이면 "근거 있음"입니다.
2. **방향**: P(상승)의 날짜 군집 AUC 개선(루트 쌍둥이 대비). 날짜 블록 부트스트랩 5% 하한이 0보다 커야 합니다.
3. **리스크 보정**: 80% 구간 적중률 ∈ [0.75, 0.85], VaR95 초과율 ∈ [0.02, 0.08].
4. **시그널 등급 검증**: Buy/Strong Buy 종목의 실현 초과수익 평균이 Hold/Sell 종목보다 큰지 봅니다. 날짜 군집 t를 씁니다.
5. **LLM 필러**: `llm_pillar`와 실현 초과수익의 순위 IC. LLM을 켜고 실행한 행만 대상입니다. EVALUATION.md 권고 1번(LLM 전진 검증)에 해당합니다.

**다중검정**: 주 지표 5개에 Benjamini–Hochberg(q = 0.10)를 적용합니다.

## 횡단면 홀드아웃(XSH)

튜닝에 한 번도 쓰지 않은 종목으로 **동결된 종목 선택 모델**을 한 번 평가합니다. 구현은 `src/quantcio/xsh.py`입니다.

**명령**
```bash
quantcio modeling select --market KR          # 선택 모델 확정(동결할 코드·설정으로)
quantcio holdout register --kind xs --market KR [--start 2019-09-27 --end 2026-09-27] [--allow-dirty]
quantcio holdout evaluate --id XSH-KR-YYYYMMDD # 1회 실행 → look 기록 (첫 유효 look만 pristine)
```

**튜닝 종목(`holdout.tuning_names`) = XSH에서 빠지는 종목**
- 시점별 모델링·팩터 백테스트 유니버스: KR은 `kr_start`(2016-01-01) 이후 매 월말 시가총액 상위 200(`backtest.kr_universe_n`)에 한 번이라도 든 엔티티, US는 `us_start`(2012-01-01) 이후 S&P 500 구성종목. 엔티티 id와 그 엔티티가 쓴 모든 티커를 함께 제외합니다.
- RSMT-Q 학습 유니버스(시점별 상위 60, 최근 7년)는 위 집합 안에 있습니다.
- `evaluate`가 쓴 오늘 목록(KR 상위 150·60, US 고정 목록)과 문서·테스트에 나오는 티커.

**XSH 종목(`xsh_candidate_names`)**
- **KR**: 매 월말 시점별 시가총액 순위 **201~400위**(`holdout.xsh_kr_rank_band`)에 든 적이 있고, 위 튜닝 종목이 아닌 엔티티. 상장폐지 종목도 실제 마지막 가격까지 포함합니다.
- **US**: S&P MidCap 400 가운데 S&P 500에 한 번도 편입되지 않은 종목(`data.pit.load_pit_xsh_universe`). 멤버십 복원 방법과 생존 편향 여부는 결과 파일의 데이터 노트에 표시됩니다.

**평가 절차(1회)**
1. `modeling select` 결과(선택 모델 이름)를 읽습니다. 결과의 코드 지문·설정 다이제스트가 현재와 다르면 XSH 행을 하나도 점수화하지 않고 거부합니다.
2. 튜닝 데이터셋으로 `modeling select`와 **같은 컨텍스트**(outer 워크포워드 블록 + 24개월 홀드아웃 블록, 정제 2h·엠바고 h)를 만듭니다.
3. 컨텍스트마다 선택 모델을 **튜닝 종목 행으로만** 내부 CV 튜닝(선택 체크포인트가 있으면 그 설정 재사용)·재학습하고, 그 컨텍스트 시험 월말의 XSH 행을 점수화합니다. 앙상블은 내부 점수 상위 3개의 순위 평균, RSMT-Q v2는 최고 후보 점수 위에 스태킹합니다.
4. XSH 특징은 XSH 횡단면 안에서 순위 정규화합니다. 날짜 단위 레짐 특징(`r_*`)은 튜닝 데이터셋 값을 씁니다.
5. 등록 기간 안의 월말 중, 학습 가능한 컨텍스트가 있는 날짜만 평가합니다(처음 36개월은 학습 이력 부족으로 제외).

**사전 등록 판정 규칙(`xsh_primary_metrics_block`, 등록 항목에 저장)**
| 주 지표 | 검정 |
|---|---|
| `xsh_auc_median`: 날짜 내 AUC(라벨 1{y_e > 날짜 중앙값}) > 0.5 | 날짜 블록 부트스트랩(3개월 블록, 2000회) 단측 p |
| `xsh_ic`: 날짜별 순위 IC > 0 | 단측 t검정(자유도 날짜 수 − 1) |
| `xsh_auc_vs_momentum`: AUC(중앙값) − 12-1 모멘텀 AUC > 0 | 날짜 블록 부트스트랩 단측 p |

- 다중검정: 세 지표에 BH(q = 0.10).
- **confirmed** = `xsh_auc_median`가 BH 후 유의 AND **AUC 95% 부트스트랩 하한 > 0.5** AND 평균 IC > 0 AND 날짜 ≥ 12.
  - 하한 조건은 2026-09-27 XSH-US 결과를 본 뒤 **추가**했습니다(아래 "결과"). 단측 p에 BH q = 0.10만으로는 p ≈ 0.09도 "유의"가 되어, 서빙 게이트(하한 > 0.5)보다 느슨했기 때문입니다. 조건을 강화하는 쪽의 변경이며, 이미 기록된 look은 추가 전용 규칙대로 그대로 둡니다. `xsh_confirmation`은 예전 항목에도 이 하한 조건을 적용합니다.
- **목표 달성(target_met)** = 평균 AUC(중앙값) ≥ `holdout.target_auc`(0.55). 사용자가 정한 목표이며 검정이 아닙니다. 신뢰구간과 함께 보고합니다.
- **민감도(판정 미사용)**: 등록 종목은 "기간 중 한 번도 상위 200에 들지 않은 종목"이라 미래 정보로 표본이 정해집니다(나중에 상위로 성장한 종목이 빠짐). 같은 순위 구간의 **모든** 시점별 행(튜닝 이력 종목 포함)으로 같은 지표를 함께 보고합니다.

**서빙과의 연결**
- 종목 선택 모델의 서빙 게이트가 통과하더라도, 주 라벨(중앙값 초과)은 v1 결과를 본 뒤 정한 것이므로(사후) **미열람 표본 확인 전까지 ×0.35 축소**를 유지합니다.
- `holdout.xsh_confirmation(market, settings)`가 "첫 look이 유효·pristine·confirmed이고 등록 당시 코드·설정이 지금과 같은 XSH"를 찾으면 그때 전체 가중으로 서빙합니다. 코드나 설정이 바뀌면 확인은 자동으로 무효가 됩니다.

**모델 범위 동결 (2026-09-27 추가)**

XSH는 종목 선택 모델만 평가하므로, 확인이 유지되는지는 **그 모델이 쓰는 코드·설정**으로 판단합니다.
- 모델 범위 코드 지문(`holdout.model_scope_fingerprint`): 신호 코드 지문에서 `llm/`, `fusion/`, `pipeline.py`, `config.py`를 더 뺀 파일들의 해시. `config.py`는 원문 대신 값으로 봅니다.
- 모델 범위 설정 다이제스트(`holdout.model_scope_digest`): `llm`·`report`·`holdout` 블록을 뺀 모든 설정 값의 해시.
- 새 XSH 항목은 두 값을 등록 때 저장합니다. 그 전에 등록된 항목은 `quantcio holdout attest-scope --id XSH-…`로 한 번 기록합니다. 이 기록은 **전체 동결이 아직 유지될 때만** 허용되고, 레지스트리의 `attestations`에 추가 전용으로 남습니다(XSH-KR/US-20260927: 모델 범위 지문 `25dc85328feb6fc5`, 설정 `a4fb8b13a5`).
- **v2: 시장별 범위(2026-09-27)**. KR 모델 경로는 `data/pit/us*`를, US 모델 경로는 `data/pit/kr*`를 실행하지 않으므로(호출 위치 확인), 시장별 범위에서 상대 시장의 PIT 모듈을 뺍니다. 등록된 두 항목은 **v1 범위가 아직 일치하는 동안**(v2 파일은 v1 파일의 부분집합이므로 등록 당시와 같음이 증명됨) v2를 기록했습니다(근거 `model_scope_v1`): KR `5d7e583d305e29af`, US `981427611ca94596`. 이후 US PIT 가격 갱신 규칙을 고쳐 US 범위는 바뀌었고(US는 원래 미확인), KR 범위는 그대로입니다.
- `xsh_confirmation`은 전체 동결 또는 (가장 높은 버전의) 모델 범위 동결 중 하나가 유지되면 확인을 인정합니다. 그래서 LLM·리포트 코드를 바꿔도 확인이 유지되고, 모델·데이터 코드나 모델 설정을 바꾸면 무효가 됩니다.
- 전진 홀드아웃(FTH)은 최종 신호(LLM 포함)를 평가하므로 계속 **전체 동결**을 씁니다.
- `holdout status`의 `모델 범위` 열에 일치 여부가 나옵니다.
- **2026-09-29 무효화**: RSMT-Q v1.1(`quant/`)과 팩터 모델 후보 선정(`backtest/`), `rsmt`·`backtest` 설정 변경으로 두 항목 모두 모델 범위가 `변경`입니다. KR 종목 선택 모델은 다시 ×0.35(배수 0.30)로 서빙됩니다. 이 두 항목은 이미 한 번 평가(look)했으므로 다시 attest하거나 재평가해도 확인이 되지 않습니다. 새 미열람 표본(예: KR 시점별 401~600위)으로 새 XSH를 등록하거나 전진 홀드아웃을 쌓아야 합니다.
- **XSH-KR-20261003**(401~600위, 확인)은 2026-10-12 배당 포함 정답의 `src` 반영으로 무효가 됐습니다.
- **XSH-KR-20261014**(601~800위, 442종목 등록, `holdout.xsh_kr_rank_band: [601, 800]`): 확인(등록 표본 AUC 0.662 [0.621, 0.706], 17개 날짜; 미래 정보로 정해진
  표본이라 과대 — 민감도 표본 1,214종목 AUC 0.569 [0.553, 0.585]). 2026-10-14부터 KR 종목 선택 모델은 배수 0.848로 서빙됩니다. KR 800위 안의 미열람 표본은 이로써 모두
  썼으므로, 다음 확인은 전진 홀드아웃(FTH-20261013)으로 합니다. 자세한 해석: [MODELING.md](MODELING.md) 56.5절.

**출력**: `reports/holdout/<id>/xsh_<id>.md`(한국어)와 `.json`. 진행 메시지에는 지표를 출력하지 않으므로, 도중에 중단되면 아무것도 보지 않은 것이고 look도 기록되지 않습니다.

## 전진 추적 원장 (`holdout/ledger/`, git 추적 대상, 추가만 가능)

**`predictions.jsonl`**: 예측 1건 = 1줄입니다.
- 키: `id = sha1(run_id|ticker)`
- 필드:
  - `run_id`, `generated_at`, `as_of`(데이터 기준일), `holdout_id`, `valid`(지문 일치 여부), `source`(`report` 또는 `snapshot`)
  - `ticker`, `market`, `last_price`, `benchmark_id`
  - `signal`, `composite`, `confidence`, `pillars`
  - `dist`: `mu`, `sigma`, `nu`, `beta`, `mu_excess`, `prob_up`, `prob_outperform`, `q10`, `q50`, `q90`, `var95`, `skill_ok`, `degraded`
  - `plan`: `entry`, `stop`, `take`, `hold_days`, `p_tp`, `p_sl`, `p_time`, `weight`
  - `llm`: `news_score`, `filings_tone`, `critic_adj`, `llm_pillar`, `skipped`
  - `config_digest`, `code_fingerprint`

**`outcomes.jsonl`**: 만기가 된 예측의 실현값입니다. `id`는 예측과 같습니다.
- `realised_at`, `r_h`(h일 로그수익), `m_h`(벤치마크), `y_e`(베타조정 초과수익)
- `up`, `beat`, `in80`, `exc95`
- `barrier_outcome`(tp, sl 또는 time), `barrier_return`, `bars_used`

**기록 규칙**
- **예측 기록 시점**
  - `run_report`가 끝날 때 자동으로 기록합니다. 등록된 FTH가 없으면 `holdout_id=null`로 기록합니다.
  - `quantcio track snapshot --market KR|US`는 유니버스 전체를 `--no-llm`으로 기록합니다. 판정 표본을 늘리는 용도이며, 주 1회 cron/launchd 실행을 권장합니다.
- **채점**: `quantcio track score`
  - 만기가 되지 않은 행은 건너뜁니다. 만기 기준은 `as_of`로부터 h거래일(h = `horizon_days`)이고, 배리어는 `hold_days`(보유기간) 기준입니다.
  - 가격은 운영 공급자에서 새로 가져옵니다.
  - `id`가 같으면 다시 기록하지 않습니다(멱등).
- **리포트**: `quantcio track report [--holdout FTH-…]`
  - 주 지표와 보조 지표를 출력하고, 표본 수와 판정 가능 여부를 함께 표시합니다.
  - 겹침 제거: 같은 종목의 스냅샷이 h거래일 안에 여러 번 있으면 판정 표본에는 **가장 이른 한 건만** 씁니다. 나머지는 참고용입니다.

## 튜닝 가드

`rsmt --tune`과 `evaluate`는 등록된 홀드아웃을 반드시 제외합니다.
- FTH의 `start_date` 이후 날짜
- XSH의 `names`

`holdout.guard_panel(panel, settings)` 함수가 이를 처리하며, 제외한 행 수를 로그와 결과(`evaluate` 리포트의 "홀드아웃 제외" 줄)에 남깁니다.
`modeling select`는 서빙 산출물도 만들기 때문에 날짜는 자르지 않고 XSH 종목만 뺍니다(`holdout.drop_xsh_names`).
레지스트리를 읽을 수 없으면 두 명령 모두 실행을 멈춥니다(보류 데이터가 새어 들어갈 수 있으므로).

**주의**: XSH 등록 **전에** 튜닝 유니버스보다 큰 유니버스(예: `evaluate --universe 300`, KR 상위 300)로 무언가를 조정하면, 그 종목들은 XSH 후보가 될 자격을 잃습니다. `tuning_names`는 그런 실행을 알 수 없으므로 문서로 금지합니다.
